## 项目简介

**Douyin Downloader / 抖音下载（网页版）** 是一款面向抖音网页版的视频、图文与作者作品保存工具。

打开作品或作者主页后，可以直接完成媒体识别、当前作品保存、图文整理、作者作品批量选择和下载任务管理，不需要反复复制作品地址。

v2.1.0 的重点不只是增加功能，而是把原本分散的下载流程重新收束为一套完整的产品体验：

- **全新 UI**：右侧 Sparkles 悬浮入口 + 抽屉式工作台；
- **更强功能**：统一任务队列、自愈恢复、安全断点续传、作者批量、多标签页协调；
- **更稳定运行**：减少任务状态冲突、错误续传、页面切换误判和多标签页抢占；
- **更低打扰**：面板收起后下载继续，只保留数量徽标、下载光圈和必要提示。

```text
当前作品 / 图文作品 / 作者批量
                │
                ▼
        统一任务队列 Unified Task Queue
                │
                ▼
       单活动执行器 / Task Group
                │
        ┌───────┴────────┐
        ▼                ▼
 浏览器页面内保存      外部下载器
        │                │
        ▼                ▼
进度 / 暂停 / 恢复    提交状态 / 外部核对
        │
        └───────┬────────┘
                ▼
   Ambient Task Status / 任务中心
```

这套结构让“点击下载”“作者批量”“暂停恢复”“新标签页继续操作”都围绕同一个任务事实源运行，减少多个模块分别判断状态造成的冲突。

## 四个核心升级

### 1. 全新 UI

v2.1.0 重做了网页内主要交互：

- 右侧 **Sparkles** 作为唯一主入口；
- 主界面采用抽屉式工作台，不遮挡整个页面；
- 当前作品、作者作品、任务、设置按场景切换；
- 无意义的选项直接隐藏，不用大量灰色按钮占空间；
- 图文作品只显示图文相关能力；
- 视频只有多种可用画质时才显示质量选择；
- 任务主要操作直接显示，次要操作收进 `⋯`；
- 统一字体、数字、间距和状态色；
- 使用 Tooltip 解释悬浮操作，不依赖额外文字堆叠。

### 2. 更强功能

新版把原本多个入口的任务能力统一起来：

- 当前视频下载；
- 图文 ZIP / 文件夹 / 逐张保存；
- 图文中的单文件保存；
- 封面；
- 原声音频；
- 弹幕；
- 作者作品批量；
- 统一队列；
- 任务暂停 / 继续 / 重试 / 取消 / 移除；
- 下载来源自愈；
- 安全断点续传；
- 多标签页任务协调。

### 3. 更稳定运行

v2.1.0 对容易产生“看起来像产品 Bug”的边界做了明确处理：

- 当前作品切换后重新核对作品身份；
- 恢复来源必须仍属于原作品和原资源；
- 一个任务失败不会自动卡住整个后续队列；
- 页面刷新 / 关闭与普通网络失败分开；
- 断点条件无法确认时不盲目追加已有文件；
- 同一抖音域多个标签页只允许一个页面内执行器真正传输；
- 新标签页不会把另一个仍在下载的标签页误判为中断。

### 4. 更低打扰

收起面板后，不需要一直把任务中心放在屏幕上。

右侧 Sparkles 会承担轻量 Ambient 状态：

- **左上徽标**：未完成任务数量；
- **外圈光环**：当前真实下载进度；
- **未知百分比阶段**：显示轻量活动态，不伪造百分比；
- **Hover / Focus**：查看百分比、剩余任务、跨标签页状态；
- **完成**：一次短暂结果反馈；
- **暂停 / 中断 / 需处理**：保留注意状态，不冒充“还在下载”。

## 功能介绍与使用流程

### 当前作品

打开普通视频或图文作品，点击右侧 Sparkles。

工具会自动读取当前作品，并根据作品类型显示对应能力。

#### 视频作品

通常可使用：

- 下载视频；
- 选择可用画质；
- 下载封面；
- 提取原声；
- 导出已读取到的弹幕；
- 查看媒体与作者信息。

下载前会再次确认当前作品来源，避免切换作品后仍使用上一条作品的旧状态。

#### 图文作品

支持：

| 保存方式 | 用途 |
| --- | --- |
| **ZIP 包** | 每个作品整理为一个压缩包 |
| **作品文件夹** | 每个作品建立独立目录，便于浏览和整理 |
| **逐张保存** | 每张图片保持独立文件 |
| **单文件** | 只保存图文中的某一项 |

默认尽量保留实际媒体格式，不因为打包而主动降低图片质量。

---

### 作者作品

进入作者主页后，主界面自动切换为“作者作品”。

重点只展示和批量操作真正有关的数据：

- **网页作品**：网页报告的作品总量；
- **已载入**：脚本当前已经建立索引的作品；
- **已选择**：准备加入下载队列的作品。

#### 扫描全部作品

扫描会滚动和读取当前作者作品列表。

- `已载入` 随扫描过程实时增加；
- 可以随时停止；
- 扫描不会自动下载；
- 不会因为选择变化反复扫描整个作者页面。

#### 批量下载

选择作品后开始批量任务：

```text
选择作品
   ↓
加入统一任务队列
   ↓
Task Group 记录批次关系
   ↓
单执行器逐项处理
   ↓
单项失败不阻塞后续任务
```

如果选择中包含已经下载的作品，会明确区分“已下载”和“新任务”，由用户决定是否重复下载。

---

### 下载任务

所有普通下载和作者批量都进入同一任务页。

| 状态 | 表示什么 | 常用下一步 |
| --- | --- | --- |
| **等待中** | 已进入队列 | 等待 / 取消 |
| **下载中** | 正在传输 | 暂停 |
| **正在写入 / 打包** | 文件仍在处理 | 等待 / 暂停 |
| **已暂停** | 当前传输已停止 | 继续 / 重新下载 |
| **页面中断** | 执行下载的页面已离开 | 恢复 / 重新检查 |
| **需处理** | 当前任务没有完成 | 重试 / 重新下载 |
| **资源不可用** | 暂未取得有效来源 | 重新检查 |
| **已提交** | 已交给浏览器或外部下载器 | 去对应下载列表核对 |
| **已完成** | 脚本确认保存流程完成 | 查看详情 / 清除 |
| **已取消** | 用户主动取消 | 重新加入 / 清除 |

“取消任务”和“移除任务”不是一回事：

- **取消**：停止该任务的传输；
- **移除**：从任务中心移除记录，不删除已经保存到磁盘的文件。

## 下载恢复与安全续传

### 来源自愈

网络地址失效时，不会无限重试同一地址。

恢复流程围绕：

1. 原作品身份；
2. 原资源身份；
3. 当前页面 / 播放器 / 已载入数据；
4. 新取得的同资源候选；
5. 有限次数重试。

如果身份不匹配，候选不会被用于当前任务。

### 安全断点续传

页面内流式写入只有在响应满足安全条件时才会继续追加：

- `206 Partial Content`；
- `Content-Range` 起点与本地偏移一致；
- 可验证的 `ETag` 或 `Last-Modified` 条件满足；
- 链接发生变化后重新验证。

如果服务端忽略 Range 返回 `200`，不会直接把完整文件追加到旧文件末尾。

## 多标签页协调

可以同时打开推荐页、作品页和作者主页。

如果标签页 A 正在下载，而标签页 B 新打开作者主页：

- A 继续执行；
- B 不会错误把 A 的任务标为“页面中断”；
- B 可以看到其他标签页正在处理任务；
- B 仍可加入新任务；
- 页面内任务等待执行权，不与 A 同时争抢写入；
- A 真正关闭或 Owner 状态失效后，遗留任务才进入恢复状态。

跨标签页只同步必要任务摘要，不同步 Cookie、Token 或文件句柄。

## 悬浮下载状态

收起抽屉不会停止下载。

Sparkles 外圈会按任务状态变化：

- 有确定百分比：按真实百分比绘制环形进度；
- 正在连接 / 准备但还没有总大小：显示活动光圈；
- 暂停后：保留已知进度并切换注意状态；
- 没有任务：光圈隐藏；
- 左上数字：表示仍未解决的任务数量。

这样不打开任务中心，也能确认“任务还在运行”。

## 保存位置

第一次使用浏览器页面内保存时，需要选择一个普通文件夹。

> [!TIP]
> 建议在桌面或其他位置先创建一个文件夹，然后选择这个文件夹。浏览器通常不会允许脚本直接授权整个“桌面 / 下载 / 文档”等系统根目录，这是浏览器的安全限制。

已经选择过的目录会尝试复用。

更换保存位置只影响后续新任务，不会把正在执行的任务突然切换到另一个目录。

## 下载方式

### 浏览器页面内保存

适合需要：

- 保存到指定文件夹；
- 查看真实传输进度；
- 页面内暂停；
- 安全断点续传；
- 图文文件夹 / ZIP 整理。

### AB Download Manager

适合希望将媒体任务交给 AB Download Manager 管理的用户。

任务显示“已提交”后，最终保存结果和目录以 AB Download Manager 为准。

### aria2

支持将任务交给 aria2。

页面可以读取 aria2 的任务进度时，会显示相应状态；真正完成结果仍以 aria2 和实际文件为准。

---

## 文件命名与重复任务

v2.1.0 的重复判断不把“标题相同”当作唯一依据。

文件与任务会优先依赖：

- 作品 ID；
- 资源身份；
- 文件类型；
- 实际下载任务上下文。

即使不同作品使用相同标题，也不会仅因为标题一致就直接认定为同一媒体。

1. 安装 Tampermonkey；
2. 点击顶部 **立即安装脚本**；

## 常见问题

### 收起抽屉会停止下载吗？

不会。

抽屉只是界面层。任务继续执行，右侧 Sparkles 会显示任务数量和下载光圈。

### 打开作者主页到新标签页会影响当前下载吗？

正常情况下不会。

v2.1.0 增加多标签页任务所有权。原标签页仍然存活时，新标签页不会将其下载误判为中断。

### 为什么“已提交”不等于“已完成”？

“已提交”表示任务已经交给浏览器或外部下载器。最终是否真正保存成功，需要在对应下载列表或磁盘中确认。

### 为什么有时不能安全续传？

为了避免文件损坏，续传必须确认远端文件仍然是同一个资源，并且服务器正确支持 Range。如果条件不足，会要求重新下载当前文件，而不是冒险追加。

### 作者主页“网页作品”和“已载入”为什么不同？

“网页作品”是页面报告的数量；“已载入”是脚本已经实际取得并建立索引的作品数。扫描过程中后者会逐步增加。
